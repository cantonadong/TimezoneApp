# 世界时钟：需求与开发方案

## 来源与阶段
依据 need.txt、dev规范.txt、1.png、2.png、3.png。独立 UI Playground 已交付。用户随后明确要求“实现完整功能让我测试”，本轮实现全部真实功能后统一交付 APK，无需中间模块再次确认。

## 业务流程及交互
1. 列表左侧统一显示 `pic/globe.png` 地球图标；城市名下只显示国家，右侧 HH:MM 下只显示 UTC 偏移，恢复 1.6 版排版。底部固定“添加城市”按钮（无加号），长列表滚动时按钮不移动。
2. 左滑城市露出红色删除操作，点击删除后显示 2 秒可撤销提示；撤销恢复原位置。原生 Toast 不能提供可点击撤销，因此正式版使用 2 秒 Snackbar 样式提示。
3. 右滑城市露出蓝色添加到桌面操作，选择白色或黑色半透明卡片，再请求系统固定小组件；不支持固定请求的桌面提供手动添加说明。
4. 添加页：可滚动的城市列表，支持中英文搜索，所有城市及底部摘要统一显示地球图标，选中项保留蓝色浅底高亮但末尾不显示对钩；进入时按当前 UTC 偏移升序排列，初始可视范围以北京行作为顶部锚点。底部选中摘要左侧为城市名与国家名，右侧为当地 HH:MM 与 UTC 偏移；保存回列表，取消不保存。重复城市禁止重复添加。
5. 桌面卡片：默认 2×1，占用空间由桌面启动器决定；黑白圆角底色均采用与参考图下方卡片接近的 60% 不透明度，HH:MM 与城市名采用较细的正常字形。每个卡片独立绑定城市与样式。卡片配置页仅可选择已添加到列表的城市，选中栏显示城市名称与 UTC 偏移，下方不再重复 UTC。弹窗没有搜索栏，左侧为地球图标，右侧为该城市当地 HH:MM。若列表为空，先提示添加城市。
6. 支持中英文，默认跟随系统；提供语言切换。正式版时间使用 IANA zone ID，夏令时和 UTC 偏移均按对应城市计算。扩展至 365 个跨各洲主要都市及首府，逐城配离线照片。应用名在中文系统为“世界时钟”、英文系统为“Timezone”，包名 `com.cantonadong.timezone`，图标使用 `pic/icon.png`。
7. 桌面小组件时间维持 40sp、字重 600 的正常字形比例，宽高按文字内容自适应，不横向或纵向拉伸；城市名称为 15sp，时间与城市作为整体在卡片中水平、垂直居中。白底和黑底使用相同的 alpha 数值 `0x99`。

## 视觉规格
白色与浅灰背景，深色主文字、灰色辅助文字，主色 #086bff；圆角城市列表、圆形地标头像、胶囊按钮；参考图所示紧凑时区信息、右对齐大号时间。安全区域避开系统栏，适配小屏幕、字体放大与长英文名称。
横滑反馈 180ms，删除提示 2000ms。预览提供暂停动效和重复演示；覆盖正常、加载、空、错误、长名称/多城市边界状态。

## 架构与方案选择
正式版推荐原生 Java Activity + Android AppWidgetProvider / RemoteViews + 本地 SharedPreferences + java.time。无需后端、登录、数据库服务或网络权限。相比跨平台框架，依赖更少且桌面小组件为原生能力；纯 WebView 不适合作为正式小组件实现。
第一模块仅用独立 HTML/CSS/JS mock UI，在 Android WebView 容器中展示，同一份预览可直接在桌面浏览器打开。模拟数据仅存内存，固定时间，不接入真实时间、存储、桌面小组件或网络。HTML 与原生正式版将共用视觉规格，正式版需在手机上确认尺寸表现。

## 开发顺序与依赖
- M0：需求、设计、环境记录。已完成。
- M1：独立交互预览与可安装 APK。已交付，用户已要求继续完整功能。
- M2：原生城市列表、城市目录、时区运算、保存/取消、滑动/撤销、语言资源、本地持久化。
- M3：基于 M2 城市模型实现原生 2×1 桌面小组件、样式配置、时间刷新、重启/时区/语言变化处理；与 M2 一起交付用户验证。
- M4：依照用户反馈修正，交付同一路径 APK。

## 验证与交付
遵照用户指令，不运行自动化或人工测试、不启动模拟器。仅执行编译、打包、签名与产物检查。用户在手机安装 APK 自行验证。每阶段更新开发日志。尚无 Git 远端，无法拉取或推送 origin/main；不虚报同步完成。始终只使用 main。
